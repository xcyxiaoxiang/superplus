  - 适用于任何需要先探索、后设计的场景

## 使用指南

### 这份模板的使用时机

探索过程中，当你发现：
- 需要回溯探索思路，或者向他人解释探索过程
- 探索内容较多，对话难以完整呈现
- 希望形成一份可归档的探索记录

那么可以参考这份模板，整理成探索报告。

### 如何根据项目复杂度裁剪

| 项目复杂度 | 建议包含的 Section（最少） |
|-----------|--------------------------|
| 低（简单集成） | 元数据 + 待确认事项 |
| 中（常规功能） | 元数据 + 技术基础 + 待确认事项 |
| 高（复杂系统） | 元数据 + 技术基础 + 现有系统分析 + 外部接口规范 + 字段映射 + 业务链路 + 配置项 + 开发模块 + 待确认事项 |

### 探索过程中如何自然形成这些 Section

不要刻意填模板。让思维自然流动，探索结束后再整理：

1. **探索中**：自由思考、画图、提问、记录关键发现
2. **探索后**：如果发现内容较多，需要归档，再回来按这份模板整理

如果探索过程中就发现某些模式很清晰，可以直接写下来——这是自然的，不是强制的。

### 与 designing 技能的衔接

探索报告 ≠ 设计文档。探索报告的作用是：
- 厘清问题空间
- 识别关键约束和风险
- 为设计文档提供输入

当探索完成后，进入 `designing` 技能时，探索报告的发现会被转化为：
- **架构设计**：从"现有系统分析"和"业务链路"提炼
- **接口设计**：从"外部接口规范"和"字段映射"提炼
- **实施计划**：从"配置项"和"开发模块清单"提炼
- **风险缓解**：从"待确认事项"提炼

### 记住

这份模板是参考，不是约束。探索的本质是自由思考，不是填写表单。如果这份模板阻碍了你的思考，就丢掉它。
